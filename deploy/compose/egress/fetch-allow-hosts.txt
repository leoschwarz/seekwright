# The paranoid fetch policy: hosts `fetch` may reach, and everything else refused.
# Not active in compose.yaml, which runs no proxy: deploy/compose/squid/fetch-strict.conf is the
# reference ACL for one in front of the fetch role. The generated copy this file renders to is
# deploy/compose/generated/fetch-allow.txt.
# Same line format as deny-hosts.txt: one host per line, and a leading dot matches the domain under it.
#
# Three things belong in a strict list before it is switched on, or the fetch tool stops working
# rather than narrowing: the hosts of the fallbacks `lib/config.ml` names by constant -- every row of
# `Config.known_fetch_fallbacks` that names one, which `ocaml-tools/egress_lists.ml` refuses to
# render a list without; the answer for a fallback the operator configures by URL, which that
# instrument reads here but cannot derive, being a host this deployment writes in its own config;
# and every host this deployment actually reads, which only the operator can name.
# The search providers' hosts are not on that list: this role runs
# `permitted_providers = []` (deploy/compose/fetch.toml), so it dispatches none of them. The two
# keyed fallbacks are the overlap: `tavily` and `linkup` are provider names *and* fallback names, so their
# hosts are required here as fallback hosts even though this role's empty set leaves those fallbacks unbuilt.

# The fetch fallbacks this tree ships, beside the constant that names each one
# (`Config.known_fetch_fallbacks` in lib/config.ml).
api.linkup.so
api.tavily.com
r.jina.ai
scrappa.co

# A fallback whose host is config rather than constant answers for itself here: `fallback=<name> <host>` names the
# host the ladder dials for it, `fallback=<name>` alone says this deployment runs no such service, and either
# way `dune runtest ocaml-tools` refuses a strict list that leaves such a fallback unanswered. After an
# edit, `dune runtest ocaml-tools --auto-promote` reprints deploy/compose/generated/fetch-allow.txt.
fallback=crawl4ai
