# Testing the OCaml port

The gate is three targets, and all three have to be green before a change is
done:

```bash
eval $(opam env --switch=default --set-switch)     # plus the GMP search paths, see plans/infra-setup.md
dune build @install        # libraries, both binaries, the .opam files
dune runtest --force       # every suite and every pinned diff
dune build @doc            # odoc, because a broken cross-reference is a defect
```

`dune runtest` is the interesting one: it runs 75 alcotest modules under `test/`
**and** the diff rules that pin whole outputs — the surface manifest, the stdio
transcript, the prose copies, the check reports. A green run means both.

## What the gate pins, beyond unit tests

| Pin | Where | What it refuses |
| --- | --- | --- |
| The frozen surface | `ocaml-tools/surface.expected`, diffed against `ocaml-tools/surface.ml`'s output | any drift in the manifest this port prints, journal fields included |
| The stdio transcript | `bin/smoke.jsonl` + `bin/smoke.toml` driven through `main.exe`, stdout and stderr pinned as `smoke.expected` / `smoke_notes.expected` | a protocol change, or a startup note leaking into the JSON-RPC channel |
| Embedded prose | `ocaml-tools/resources.ml` prints each literal in `lib/prompts.ml` and `lib/dashboard_html.ml`, diffed against the `.expected` golden beside the printer | a deployed sentence, or the dashboard page, changing without a reader noticing |
| The documented example | `ocaml-docs/reference-config.md` and `ocaml-docs/deploying.md`, parsed and loaded by `test_config.ml` | a documented key, a secrets checklist entry, or a role block that would not load on this port |
| `lib/router.ml`'s isolation | `test/router_dependencies.expected`, generated by `ocamldep` | the routing module gaining a dependency on `seekwright` |
| Log discipline | `test/log_guard/` walks the AST | a traceback, a secret, or an f-string-style log call reaching a call site |
| Negative compilation | `test/should_not_compile/` | code that forges a capability grant, or a `.mli` that leaks one |
| The `--check` report | `bin/check_unbuilt*.expected`, and `test/check_transitional*.expected`, `test/check_unreachable*.expected`, `test/check_probe_gap*.expected` — each pinned with the exit code the run is allowed to have | a route reported ready, or reported a fault, on evidence the report does not have: an unbuilt name probed as if it were built, a missing probe counted against the deployment, a down probe left uncounted |
| Client usage | `test/cli_usage_*.expected`, `test/cli_startup_*.expected` | a flag or startup line changing shape |

A diff rule that fails is usually a legitimate re-pin: `dune promote` promotes
what a **runtest** diff flagged (a bare `dune build <target>` says "nothing to
promote"), one mismatched file per run, and the promoted file lands read-only —
`chmod +w` it before committing. `test/router_dependencies.expected` is the
frequent one: any module added under `lib/` adds `ocamldep` lines.

To re-run one suite while iterating:

```bash
./_build/default/test/test_engine.exe test "<suite name>"
```

Note the test binary's working directory: suites that read repository files expect
`_build/default/test/` (their `(deps …)` carry the `../` paths), so running them
from the repo root fails exactly those cases.

## The differential harness — a pinned behaviour baseline

`test/differential/` answers one question: for the same input, does this behaviour still
hold against the answer pinned for it? Ten areas — `config`, `engine`, `fetch`,
`jsondoc`, `model`, `provider`, `router`, `sanitize`, `tabledoc`, `text` — 413
goldens, each taken once from the Python modules' own answers and, where this port
deliberately disagrees, pinning **both** answers. The corpus and the goldens are
committed data, and `dune runtest` re-runs only the port's projection, so the gate
needs no Python, no network and no keys.

**Regeneration is frozen** (2026-11-16): no new corpus case, no re-pinned golden, no
closing a registered divergence. `plans/retiring-the-python-tree.md` holds the decision
and the steps that end in deleting the Python tree; the port's half of that generator,
`test/differential/drive.exe`, is deleted as well, so nothing in this checkout can print
a candidate golden and a golden moves only by an edit. `plans/evidence-tiers.md` says
what a green differential suite is evidence *about* — and what it has never been
evidence of, which is a provider answering the way a fixture once said it did.

Two suites consume the pinned data: `test_differential_golden` (the projection must
equal the pinned answer, a floor per area, and every corpus input must have a golden)
and `test_differential_matrix` (the four tables under `test/differential/matrix/` —
`behaviours`, `config-fields`, `providers`, `surface` — whose `baseline` column names
the surviving evidence for a row: a `differential:<area>` corpus area, or the suite
that pins it).

A divergence is registered rather than smoothed over: such a golden carries
`verification: explicit-divergence` and a `reason` line, pins the port's answer next
to the Python answer, and fails if either changes shape — including a difference that
closes on its own. Each registered difference is a row in
`test/differential/divergences.tsv`, and `test_differential_matrix` holds the rows and
the `explicit-divergence` goldens to each other in both directions — a row without its
golden, a golden without a row and a row whose reason does not repeat in the golden's
header all fail there. Two shapes are systematic and carry no row of their own: the
`fetch.extractor` default, and pydantic's structured validation report against this
port's one sentence. The corpus and the goldens are a committed baseline, and
regeneration is closed: re-deriving them would need a checkout of the implementation
the baseline was taken from, which this branch does not carry.

## Conformance against the official runner

`test/conformance/` runs the pinned `@modelcontextprotocol/conformance` runner
against the port's HTTP server and scores it through
`application-classification-2026-07-28-server.json`. Measured 2026-11-13:
**90/90 applicable checks pass**, with 4 applicable + 3 mixed + 43 excluded
scenarios each keeping its recorded status; the raw runner tally (8/37) is a
footnote in `plans/seekwright-ocaml-port.md` §16 because a three-tool server
cannot score scenarios whose declarations it does not declare. The runner needs
Node ≥ 22 and the scenarios are not in the opam package — `live`-style setup, not
part of the gate. Its rules and traps are in the `ocaml` skill's
"Conformance runner" section.

## Extraction quality is measured, not asserted

`test/corpus_html/` holds the fixture corpus; `ocaml-tools/extract_bench/` carries
the bar and the metric definitions. The gate enforces the per-case bar in
`test/corpus_html/cases.json` (`bench.exe --check`), and adds a byte-level pin
beside it: `parity/port-stdlib.txt` and `parity/oracle-stdlib.txt` are digests of
what each side's `stdlib` backend produced, checked by
`digest_cases.exe --check-parity`, because a quality bar cannot pin bytes. The
three-backend table in `test/corpus_html/metrics.md` is the one the benchmark's
Python half printed before this tree was retired: recorded evidence, not a gate
step the branch can rerun. This is where the PDF refusal and the boilerplate
numbers in [`divergences.md`](divergences.md) come from.

## Live runs are outside the gate

`dune runtest` dials nothing, by construction. The live half is the separate
`seekwright-live` binary and its gate variable — see
[`live-tests.md`](live-tests.md) — and a live run counts as evidence only once
`plans/seekwright-ocaml-port.md`'s live-run table carries its row.
