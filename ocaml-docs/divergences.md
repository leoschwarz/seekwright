# What this port does differently

Read this before moving a deployment from the Python implementation to the OCaml
one. The tool surface is the same; the runtime, the extraction backend and two
config keys are not. Every claim here names a symbol in this tree, and the
differences that reach a caller are pinned by goldens, not by prose.

## Same surface, one guard for both trees

The three MCP tools and their parameters, the three `POST /api/v1/…` routes, the
four operational routes, the three client verbs, the ten server flags, the
seventeen provider names, every config key and the thirty-seven usage-journal
fields are identical. `ocaml-tools/surface.ml` prints that manifest in the same
body format `tools/surface.py` prints, `ocaml-tools/surface.expected` pins the
full OCaml rendering, and a `runtest` rule diffs the Python-compatible body
against the body of `docs/reference/surface.md`. Any drift in either tree fails
`dune runtest` in both directions.

## One binary, one process

| Python deployment | This port |
| --- | --- |
| CPython + FastMCP + uvicorn + httpx | one native binary, `seekwright` |
| uvicorn's server loop, per-request worker semantics | one Eio event loop, one process, fibers |
| `pip`/`uv` install, interpreter and site-packages on disk | the binary plus `gmp` and `ca-certificates` in the image |
| stdio and streamable HTTP over uvicorn | stdio over `mcp-kit.stdio`, HTTP over `cohttp-eio` |

The HTTP path drains on SIGTERM/SIGINT under `Server.drain_grace_seconds` (10s):
accepting stops, the operational `GET`s answer 503 `{"status":"stopping"}`, the
REST projection answers 503 `{"error":"The server is stopping; retry shortly."}`,
in-flight calls finish, then the process exits 0. Signals are handled on the HTTP
path only — under stdio, EOF on stdin is the shutdown signal.

`seekwright` has **no `--help` and no `--version` flag**. An unknown flag is a
usage error: `seekwright: unknown flag --help`, exit 2. Usage prose lives in
`README.ocaml.md`; the binary's contract is the flag list the surface golden
prints.

## `fetch.extractor` is `stdlib`, and that is the whole difference in extraction

`config.known_extractors` is `["stdlib"]`. `trafilatura` is a Python-only
registry member — its library does not ride here, so naming it is refused when
the config is read rather than failing at the first fetch. Consequences an
operator can feel:

- **The answer shape is the same; the cleanliness is not.** Over the 32-case
  corpus, `ocaml-stdlib` and `python-stdlib` give the identical shape — 24 texts
  and 7 named refusals — and hold comparable substance: 84/89 essential phrases
  against the Python reader's 79/89. What the port's reader leaks is the
  furniture: 34/35 boiler rows against 18/35, and trafilatura's 2/35. Against
  trafilatura the port is also ~120× faster on that machine (43.3 ms median
  against 5374.6 ms) and far kinder to unicode (32 cases clean against 20). The
  per-case bar the gate enforces is `test/corpus_html/cases.json`; the
  measurement it was derived from is `test/corpus_html/metrics.md`, generated by
  `ocaml-tools/extract_bench/metrics_table.py`.
- **PDFs are refused — by the backend, not by the port.** `pdf-minimal` and
  `pdf-two-pages` come back as a named refusal from `ocaml-stdlib` *and* from
  `python-stdlib`; only trafilatura returns text. The Python deployment's default
  is trafilatura, so PDF works there by default; a Python operator who had set
  `fetch.extractor = "stdlib"` already had this refusal. On this port the
  sentence is
  `cannot extract text from application/pdf; this tool reads HTML, plain text, JSON, CSV`
  (the `type_refusal` path in `lib/fetch/fetcher.ml`), and a truncated PDF is
  refused for its own reason: the xref table is at the end of the file, so a
  partial download is not a document. This is a measured exclusion, recorded in
  `plans/seekwright-ocaml-port.md`, not an oversight to work around with a key.
- **JSON and CSV read the same way as Python.** `jsondoc` and `tabledoc` are
  stdlib-only ports of the same line grammar, so `fetch(path=…)` and
  `fetch(structure=true)` behave identically; the differential goldens cover them
  (`jsondoc`, `tabledoc` areas).

## Two config keys are read and refused

`[logging] library_level` and `[logging] access_log` are uvicorn's knobs, and
there is no uvicorn here. Both keys exist (the config grammar is shared), both
are parsed, and setting either to a non-default value is a load-time refusal
naming the reason. Everything else in `[logging]` works.

## Live verification is thinner than the shipped surface

All seventeen names are registered and buildable (`lib/factory/registry.ml`).
Live verification in this build has passed for `freeserp`, `anysearch`,
`exa:free` and `parallel:free` — the whole keyless default set — and for the
`fetch:local` read and the `fetch:metadata` refusal. Every other name sits on
`--check`'s `untested` line until a keyed gated run passes, and the four keyed
fetch fallbacks (`fetch:scrappa`, `fetch:tavily`, `fetch:linkup`, and
`fetch:jina`, which is keyless but has not been selected) are constructed and
exercised hermetically without having reached their real endpoints. The runs and
their dates are the live-run table in `plans/seekwright-ocaml-port.md` and in
[`live-tests.md`](live-tests.md).

## Egress and trust store

- **No outbound proxy.** The Python deployment inherits httpx's
  `HTTPS_PROXY`/`NO_PROXY` handling; this port dials the endpoint in its registry
  row directly. If your egress policy requires a proxy, that is a gap to plan
  around — see [`egress.md`](egress.md) for the endpoint list to allow.
- **Trust anchors come from the OS store.** `Policy_net` builds its TLS config
  once per grant from `Ca_certs.authenticator ()`, which reads the OS store, or
  `SSL_CERT_FILE` when set. A missing store is a startup failure, not a handshake
  failure, and there is no accept-any path.
- **The RNG is installed at startup.** `bin/main.ml` calls
  `Mirage_crypto_rng_unix.use_default ()` before flag parsing, because a missing
  generator would otherwise surface at TLS handshake time.

## What a caller cannot tell apart

The wire contract is deliberately unchanged: a tool failure is a 200 with
`isError`, the REST projection's refusals are the same sentences, unset fields
never serialise as `null`, `sanitize_text` still breaks model special-token
literals with a U+200B, and the routing decisions live in `lib/router.ml`, which
imports nothing from `seekwright` — a dependency pin (`test/router_dependencies.expected`)
keeps that true. Cross-tree behaviour is checked by the differential harness:
ten areas of pinned goldens generated from the Python implementation's own
modules, and every registered difference between the two answers is listed, with
its reason, in `ocaml-tools/oracle/README.md`'s `DIVERGENCES` table. The two
systematic registered shapes are exactly the two decisions above: the extractor
default, and pydantic's structured validation report where the port states one
sentence.
